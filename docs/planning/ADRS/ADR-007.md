# ADR-007 Clock-Drift & Jitter Policy

Status: Accepted-default (PENDING B0 drift/jitter spike before final constants)

## Context
Two+ independent clocks (emitter capture, receiver render, DAC crystal via USB isochronous). Must detect drift, keep buffer bounded, no oscillation, never mislabel resampled path.

## Options
1. Receiver-side bounded adaptive resampling (rubato) driven by an estimator (default).
2. Receiver feedback to emitter to nudge capture rate (needs cross-clock control, usually not available on stock OS).
3. Sample-slip insertion/deletion at frame boundaries (audible artifacts if unmanaged).
4. None (unbounded buffer growth / underruns).

## Evidence
- P1 review: WLS estimator over emitter-sample-counter-vs-arrival deltas with outlier rejection; deadband + slew ≤0.5–1 ppm per ~1 Hz update; warm-up via prefill seeding; failure model (delta > N ppm) → renegotiate with confirm, never silent.
- Jitter profiles: Low/Balanced/Resilient with sizing inequalities (ring_capacity ≥ 2×(max_jitter+reorder_window)/frame_period; slew < buffer headroom).

## Decision
Receiver-driven bounded adaptive resampling (rubato) + estimator as above; explicit drift-injection tests (measured synthetic ± ppm); resampled path never labeled bit-perfect; fidelity state reflects actual applied conversion (converted vs unverified vs bit-perfect); buffer profiles measurable and non-oscillating.

## Consequences
Robust to real-world oscillators; the price is that drift-corrected playbacks are never "bit-perfect" — surfaced honestly in UI.
## Reversal
Measurement shows audible artifacts within the defined bounds; estimator fails to converge within target time; a platform exposes true DAC-clock-slaved capture making slip-free bit-perfect feasible.
