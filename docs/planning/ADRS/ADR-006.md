# ADR-006 Discovery & Pairing

Status: Accepted (2026-09-06)

## Context
FR-003 local discovery with manual/QR fallback; FR-004 secure pairing with persistence/revocation and no unauthenticated injection.

## Options
1. mDNS (mdns-sd) + manual IP + QR fallback; Noise XX + ed25519 persistent identity; SAS/QR confirmation.
2. mDNS + TLS-PSK / pre-shared codes.
3. Central rendezvous (excluded: no cloud).

## Evidence
- mDNS browse/advertise mature (mdns-sd 0.21.2, permissive); iOS local-network permission + NSBonjourServices requirement verified; Windows/macOS/Linux fine.
- Reviewer: identity = ed25519 fingerprint; never trust mDNS identity; SAS/QR bind to handshake pubkey; revocation with map-style versioning + offline QR propagation; rate limits; 0-RTT off for media.

## Decision
mDNS `_wdr._tcp` advertisement (privacy-minimized TXT, no identity/device data) + manual IP + QR fallback. Pairing: Noise XX over control stream, ed25519 identity, X25519 ephemeral (forward secrecy), SAS/QR confirmation bound to actual handshake pubkey, confirmed-flag stored atomically with key, re-confirm on rotation. Trust store per-OS secure storage; revocation records signed + versioned + QR-propagated offline; "forget all". Bounds in PROTOCOL_SPEC.

## Consequences
Strong local security without cloud; UX cost of explicit pairing on first connect.
## Reversal
Discovery protocol requirement change (e.g., mandated central directory) or an OS security improvement to key storage changes bounds.
