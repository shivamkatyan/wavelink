# ADR-003 Network Transport

Status: Accepted (transport selection + CC); BBR-vs-CUBIC decided by the t-P1-cc netem spike → keep CUBIC (2026-09-08); datagram viability confirmed at the degraded profile.

## Context
LAN audio relay (unicast, low latency, lossy + lossless, encrypt+auth, reconnect/path change, all 5 desktop+mobile targets).

## Options
1. QUIC (quinn 0.11, rustls-ring default): reliable control streams + unreliable datagrams for lossy audio; 0-RTT; connection migration/reconnect.
2. RTP/RTCP + SRTP (webrtc-rs rtp/rtcp/srtp) over UDP + separate control: standard timing/report machinery; interop surface.
3. Custom framed UDP protocol.

## Evidence
- quinn 0.11.11 active, rustls-ring pure-Rust (cross-compiles iOS/Android), datagram API present, migration supported. RTP stack mature too, but requires hand-building keying/replay/versioning and lacks single-connection migration.
- Reviewer findings folded in: lossless MUST ride a reliable stream (FLAC/PCM have no PLC; datagrams are lossy by design); datagram credit starvation and CC collapse under loss must be measured (B0 spike); 0-RTT disabled for media (replayable).
- RFC 9221: datagrams forbidden in 0-RTT.

## Decision
QUIC via quinn: reliable control stream(s) + unreliable datagrams for lossy audio; lossless over a reliable stream with bounded latency budget + retransmit deadline (≤50 ms) + per-frame CRC. BBR vs CUBIC chosen by netem spike; document exit criteria to re-open ADR (interop surface → RTP; measured CC collapse unfixable → UDP/RTP data plane).

## Consequences
One port/NAT-friendly; built-in flow+CC; versioned self-describing wire. Cost: bespoke timing/report machinery in-app (SR/RR substitute).
## Reversal
Any interop surface requirement, or measured quinn datagram starvation under target degraded profile that redundancy/FEC cannot fix.

## Spike result (t-P1-cc, 2026-09-08) — BBR vs CUBIC decided by netem

**CC decision: keep CUBIC.** Measured on the reference lossy Opus datagram
lane (`ref_emitter`→`ref_receiver`, 20 ms cadence, compose netem bridge),
16 trials (4/CC/profile, 250 frames each; defective EOS-loss trials retried).

| profile | CC | recv | loss (median) | late | underruns | fatal | cwnd (B) | queue ≤512 |
|---|---|---|---|---|---|---|---|---|
| clean | Cubic | 250 | 0 | 0 | 0 | 0 | 12 000 | ✅ |
| clean | Bbr | 250 | 0 | 0 | 0 | 0 | 359 448 | ✅ |
| degraded (1% loss+30ms jitter) | Cubic | 246 | 4.0 | 0 | 0 | 0 | 2 904 | ✅ |
| degraded | Bbr | 247 | 3.0 | 0 | 0 | 0 | 349 312 | ✅ |

Under the ADR-003 degraded profile Cubic and Bbr are statistically equivalent
on every audio-health metric (median loss 4.0 vs 3.0 ≈ the injected 1%;
late=0, underruns=0, no panic, queue bound honored). Bbr holds a ~350 KB
congestion window where Cubic collapses to ~2.9 KB, but at WDR's 20 ms×~400 B
datagram load that headroom is not needed and buys nothing measurable. Cubic
is quinn's default (best-tested, no extra wiring) → **no switch, no reopen
trigger**. BBR remains selectable via `WDR_CC=bbr` for any later LAN/high-rate
profile that shows an advantage.

Exit-criteria status: interop surface → RTP required = **NO reopen**; measured
datagram starvation under degraded profile = **not observed** (late=0,
underruns=0, queue bounded) → redundancy/FEC fallback not invoked, though it
remains the escalation if a harsher profile is adopted.
