# ADR-005 Lossless PCM / Compression Strategy

Status: Accepted-default (PENDING the B0 codec benchmark before final lock)

## Context
Pro Wi-Fi lossless. Need low CPU, acceptable bandwidth, format support (16/24-bit integer at 44.1/48 kHz first), low latency. Worst-case incompressible fixtures matter (24-bit 48k stereo ≈ 2.88 Mbps raw ≈ 360 KB/s ≈ 2.3 Mbps FLAC-incompressible).

## Options
1. Raw uncompressed PCM (zero CPU, bit-perfect by construction, bandwidth ~1.4–2.9 Mbps).
2. FLAC real-time (libflac; ~40–60% typical music, ~1.0 ratio on noise; encode CPU moderate).
3. Other lossless (ALAC — Apple-centric; WavPack — smaller ecosystem in Rust).

## Evidence
- Truth model from P1 review: lossless frames MUST ride a reliable stream (no concealment). Bit-perfect only claims what can be measured with a hardware loopback / USB analyzer; bounded silent sample-slip semantics; never resampled, never drift-corrected (that's "converted"/"unverified").
- FLAC small fixed blocks (~240 samples @48k) keep latency low; per-frame CRC gives delivery integrity.
- Rust: flac-bound/libflac-sys (encode), claxon (decode), hound (PCM).

## Decision
Default FLAC with a raw-PCM profile; per-frame CRC on every lossless frame; CI frame-size calculator enforcing payload ≤4 KB (or negotiated max_datagram/stream budget); fidelity machine per ARCHITECTURE. B0 benchmark (real music + worst-case incompressible) decides FLAC-vs-PCM default at each required format and records payload/on-wire bandwidth, encode/decode CPU, frame duration, algorithmic delay.

## Consequences
Lossless integrity proven by PCM hash equality; bandwidth budget measureable and published. Cost: PCM profile doubles bandwidth for those who choose it.
## Reversal
Benchmark shows raw PCM preferable on CPU/latency at required formats, or FLAC cross-compile overhead unacceptable.
