# ADR-002 UI / Platform-Shell Strategy

Status: Accepted (2026-09-06)

## Context
UI must not hide critical audio lifecycle behavior (route changes, permissions, background modes, FGS). Cross-platform UI kits abstract these.

## Options
1. Native UI shells per platform (Kotlin/Compose, SwiftUI, WPF, GTK4).
2. Cross-platform UI toolkit (egui/Tauri/Flutter) + native plugins.
3. Cross-platform WebView shell.

## Evidence
- P0 research: platform-specific audio lifecycle APIs (AVAudioSession categories/background modes, Android FGS types + permissions, WASAPI route events, PipeWire) are required; a generic toolkit that hides these jeopardizes FR-015/FR-016/FR-052.
- Reviewer finding: RT path must not cross FFI on iOS (uniffi only for control, not render callback).

## Decision
Native UI per shell; shared core speaks to shells via uniffi/jni on non-RT interfaces only. Linux gets the headless sim first (CLI), a GTK4 shell later.

## Consequences
More per-platform UI work but correct lifecycle behavior; accessibility per-platform tooling (FR-056).
## Reversal
If a shell fails FR-056 accessibility, split that shell's UI to a more capable toolkit while keeping the core.
