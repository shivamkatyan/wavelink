# Architecture Decision Records — Index and Summary

Full ADRs live in `docs/planning/ADRS/ADR-00N.md`. Status: `Accepted` = fixed by evidence; `Accepted-default` = default chosen, measured/validated in B0 spikes before final lock.

- **ADR-001 (Accepted)** — Repo strategy: monorepo; Rust shared core (`core/`) + native shells. Rationale: memory safety, ecosystem maturity (quinn/rustls/Opus/FLAC/Noise), Linux/WSL2/Docker testability, cross-compile via zigbuild/cargo-ndk/uniffi. Reversal: if a core stage's C-interop cost exceeds Rust benefit, keep Rust for new code and wrap.
- **ADR-002 (Accepted)** — UI/platform-shell strategy: native shells (Kotlin/Compose, SwiftUI, WPF, GTK4, Linux console sim). Cross-platform UI toolkit rejected (hides audio lifecycle). Reversal: if a shell cannot meet FR-056 accessibility, split out a more capable UI.
- **ADR-003 (Accepted, B0 spike)** — Transport: QUIC (quinn 0.11, rustls-ring default). Reliable control streams; **lossy media over unreliable datagrams; lossless over a reliable stream with retransmit deadline**. 0-RTT disabled for media. BBR vs CUBIC decided by netem spike. Exit criteria to re-open: interop surface → RTP/SRTP; measured CC collapse under 1% loss unfixable by BBR/redundancy.
- **ADR-004 (Accepted)** — Lossy codec: Opus (wrap libopus via `opus`/`opusic-sys`, fixed-point for ARM). Settings per PROTOCOL_SPEC.
- **ADR-005 (Accepted-default, B0 bench)** — Lossless: FLAC (libflac) vs raw PCM — measured on real music + worst-case incompressible fixtures (CPU/bandwidth/latency at 44.1/48k 16/24-bit); default FLAC with PCM profile, per-frame CRC, CI frame-size calculator. Fidelity states: `Lossy transport` / `Lossless transport, output converted` / `Lossless transport, unverified` / `Lossless transport, bit-perfect verified` (verified only by hardware digital loopback/USB analyzer trace stating clock relationship + bounded silent sample-slip budget). Bit-perfect = source samples bit-identical into DAC with capped silent-envelope slip events (≤K/hour); explicitly not resampled, not drift-corrected.
- **ADR-006 (Accepted)** — Discovery & pairing: mDNS (mdns-sd) + manual IP/QR; Noise XX + ed25519 + SAS/QR pubkey binding; trust store + revocation with offline QR propagation.
- **ADR-007 (Accepted-default, B0 spike)** — Clock drift/jitter: receiver-side bounded adaptive resampling (rubato) driven by WLS estimator over emitter-sample-counter-vs-arrival deltas with outlier rejection; deadband + slew ≤0.5–1 ppm per ~1 Hz update; warm-up via prefill seeding; failure (clock delta > N ppm) → renegotiate lossless→lossy with confirm, never silent. Jitter-profile sizing inequalities: `ring_capacity ≥ 2×(max_jitter + reorder_window)/frame_period`; drift guard slew < buffer headroom. Resampled path never labeled bit-perfect.
- **ADR-008 (Accepted)** — Min OS: Windows 11 24H2+ (Win10 22H2 EOL-legacy/own-risk); macOS 13 (per-app taps feature-gated 14.2+); Linux Ubuntu 22.04+/glibc≥2.35, PipeWire≥1.4; Android minSdk 29 target 34+ (receiver 26 acceptable); iOS 14 floor (SCK emitter path 27+, ReplayKit 12–26). Justified from P0 lifecycle/API evidence.
- **ADR-009 (Accepted)** — Bluetooth boundaries (two-axis truth model): (1) standard BT sink receive = Linux only; (2) custom product-peer RFCOMM/L2CAP transport = Android/Windows-RFCOMM/Linux at low-bitrate lossy (app renders to its own output/DAC; not an OS audio path; per-platform throughput budget table measured in B5; iOS MFi-scoped, not for the general product). UI/docs state which cells work, with one-action fallback to free lossy Wi-Fi. Never imply a stock phone can be an A2DP sink.
- **ADR-010 (Accepted)** — Packaging/update: MSIX+EXE; DMG/Developer ID + notarization dry-run; deb/rpm/AppImage/Flatpak; APK/AAB (keystore self-generated now); TestFlight/App Store path. Auto-update via platform mechanisms (no bespoke updater). Signing/store jobs packaged as gated, ready on credentials.
