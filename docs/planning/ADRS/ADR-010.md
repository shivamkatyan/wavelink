# ADR-010 Packaging & Update Approach

Status: Accepted (2026-09-06)

## Context
Installable dev + release artifacts without credentials; auto-update where possible; signing jobs ready but gated.

## Options
1. Per-platform packaging (MSIX/EXE, DMG, deb/rpm/AppImage/Flatpak, APK/AAB, TestFlight/AppStore) + platform-native update.
2. Bespoke cross-platform updater (extra attack surface; not needed pre-release).

## Evidence
- P0: Windows has no notarization (SmartScreen reputation instead); Azure Artifact Signing / Store re-sign; macOS Developer ID + notarytool + hardened runtime; Android Play App Signing (upload key); iOS App Store Connect/TestFlight; Linux Flatpak perms (pulseaudio/PipeWire socket, bluetooth, USB portal, bluez talk).

## Decision
Packaging/update per platform via native tooling; no bespoke updater; signing/store steps implemented as gated jobs that run on credential presence; unsigned artifacts + dry-runs produced now (missing creds never blocks packaging logic).

## Consequences
Releaseable without credentials; store publication deferred to credential gate.
## Reversal
A cross-platform auto-update requirement (e.g., enterprise fleet) would re-open with a signed-update design.
